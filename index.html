Das Problem mit KI-Agenten

Jeder spricht von KI-Agenten. Aber kaum jemand lässt sie wirklich 24/7 laufen.

💸

Token-Kosten explodieren

Jeder API-Aufruf kostet Geld. Ein Agent, der stündlich recherchiert, produziert schnell hunderte Euro pro Monat – bei begrenzter Qualität der Gratis-Tiere.

🔒

Datenschutz bei Free-Tiern

Kunden- und Unternehmensdaten an kostenlose LLM-Gateways zu schicken, ist riskant. Namen, KPIs und Strategien dürfen nicht nach draußen gelangen.

🧩

Komplexität ohne Struktur

KI-Agenten ohne Architektur verheddern sich: Halluzinationen, Endlosschleifen, unbrauchbare Ausgaben. Ohne Manager/Worker-Pattern herrscht Chaos.

Die Lösung: Manager/Worker-Architektur

Ein bezahlter Manager sanitisiert Briefings. Kostenlose Worker erledigen die Arbeit.

🧠 Manager (lokal, bezahlt)

Liest Kunden-Briefing → anonymisiert → startet Worker → prüft Ergebnisse

↓

localhost:20128 · 115+ kostenlose Modelle · kein API-Key nötig

↓
🔍 Mitbewerber-Scout
✍️ Content-Creator
🚦 Reality-Checker
📈 USP-Stratege
🎯 Lead-Recherche
↓

📂 Output-Ordner (Obsidian/Notion)

Ergebnisse als Markdown → Sync zu Notion-Kanban → Telegram-Push-Benachrichtigung


🔑 Das Datenschutz-Prinzip

Der Manager entfernt vor der Weitergabe an Worker alle Firmennamen, Personennamen, konkrete Zahlen und internen Systembezeichnungen. Die Worker erhalten nur ein anonymisiertes Problem-Profil (Branche, Größenklasse, Schmerzpunkt) – nützlich genug für gute Ergebnisse, sicher genug für echte Daten. Die Worker werden explizit angewiesen: "Eingabe ist anonymisiert – keine echten Namen verwenden, nichts erfinden."

Schritt-für-Schritt-Anleitung

In 5 Schritten zur eigenen KI-Agenten-Pipeline. Voraussetzung: Node.js ≥ 22.

1

OmniRoute installieren

OmniRoute ist ein kostenloser LLM-Gateway – kein API-Key, keine Anmeldung. Er leitet Anfragen an kostenlose Modelle weiter.

# Node.js ≥ 22 benötigt (node --version prüfen) npm install -g omniroute omniroute --version # z.B. 3.8.49 omniroute # startet Server auf http://localhost:20128 # Modelle anzeigen (115+ kostenlose Modelle): curl -s http://localhost:20128/v1/models | head -c 400
2

Hermes installieren

Hermes Agent ist das Framework, das die Agenten steuert – Tools, Memory, Cron-Jobs, Messaging.

# Hermes installieren (einmalig) curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash # Setup-Wizard starten hermes setup # Testen hermes chat -q "Was ist die Hauptstadt von Frankreich?"
3

OmniRoute-Profil erstellen

Ein separates Hermes-Profil zeigt auf OmniRoute. So bleiben bezahlte und kostenlose Agenten getrennt.

# Profil erstellen hermes profile create omniroute-workers # Profil auf OmniRoute zeigen hermes -p omniroute-workers config set model.provider custom hermes -p omniroute-workers config set model.base_url http://localhost:20128/v1 hermes -p omniroute-workers config set model.default oc/deepseek-v4-flash-free hermes -p omniroute-workers config set model.api_key dummy # Test hermes -p omniroute-workers chat -q "Antworte nur mit: OK"

⚠️ Wichtig: Statt model: "auto" immer ein konkretes Modell setzen (z.B. oc/deepseek-v4-flash-free). "auto" führt häufig zu HTTP 503 (überlastete Gratis-Pools).

4

Cron-Agenten einrichten

Jeder Agent wird als Cron-Job angelegt – er feuert automatisch zur eingestellten Zeit. Der Prompt muss vollständig selbsterklärend sein.

# Mitbewerber-Beobachtung jeden Werktag um 07:00 Uhr hermes -p omniroute-workers cron create "0 7 * * 1-6" \ "Du bist der Mitbewerber-Scout-Agent. KONTEXT: KMU im Maschinenbau/Sondermaschinenbau, DACH-Region. AUFGABE: Recherche 3 aktuelle Trends von Mitbewerbern. Schreibe Markdown nach ~/agents/output/mitbewerber-$(date +%F).md. Antworte mit max. 3 Zeilen." \ --name "Mitbewerber-Scout" --deliver local # Gateway aktivieren (Windows: Startup-Eintrag) hermes -p omniroute-workers gateway install hermes -p omniroute-workers gateway start hermes -p omniroute-workers gateway status # "Ticker heartbeat: 5s ago"
5

Manager-Pipeline bauen (Datenschutz)

Der Manager ist Ihr lokaler, bezahlter Hermes (Default-Profil). Er sanitisiert Briefings und prüft Worker-Ergebnisse.

# Manager sanitisiert Briefing (Python-Skript, lokaler Prozess) # 1. Kunden-Briefing lesen # 2. Firmennamen, KPIs, Personen entfernen # 3. Anonymisiertes Briefing nach ~/agents/briefings/ schreiben # 4. Worker-Cron feuert, liest Briefing, schreibt Output # 5. Manager prüft Output → Sync zu Notion → Telegram-Push # Tokenfreie Telegram-Benachrichtigung (Watchdog-Pattern): # no_agent Cron-Job mit --script fragt Notion-DB ab # Wenn neue Karten im Status "Entwurf" → print summary → Telegram # Wenn nichts neues → leerer stdout → silent (keine Nachricht)
